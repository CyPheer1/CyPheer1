# CyPheer1 profile deployment

## Activate

1. Publish this folder's README, workflow, scripts and tests to the default branch of the public repository **CyPheer1/CyPheer1**. GitHub displays a profile README only when the repository name matches the username. The local project folder is named **CyPheer1**.
2. In repository **Settings > Actions > General**, allow Actions and permit workflows to write repository contents. Organization policies and branch protection must also allow the bot's commit. No personal access token is required for this public-data configuration.
3. Open **Actions > Update profile > Run workflow** on the default branch. The workflow is also triggered by changes to the README, updater, tests or workflow. Its identity guard intentionally skips every repository except `CyPheer1/CyPheer1`.
4. Confirm that `assets/stats-dark.svg`, `assets/stats-light.svg`, `assets/streak-dark.svg` and `assets/streak-light.svg` were committed. The updater automatically changes the README's remote card URLs to these local snapshots as each valid card becomes available.

The workflow is scheduled daily at **06:23 UTC**. Schedules can be delayed; GitHub can disable scheduled workflows in public repositories after 60 days of inactivity. Re-enable the workflow in Actions when necessary. There are no artificial keepalive commits or fabricated contributions.

## What updates

| Component | Source | Refresh |
| --- | --- | --- |
| Header | Capsule Render + readme-typing-svg | Rendered SVG animation; subject to image caching |
| Skill grid | skill-icons | Theme-aware images; stack selection stays editorial |
| GitHub statistics | GitHub Readme Stats Action, recommended by the original GitHub Readme Stats project | Daily, generated on the runner |
| Contribution streak | GitHub Readme Streak Stats Action | Daily, generated on the runner; Casablanca timezone |
| Quest log | GitHub REST public events | Daily, newest five supported distinct date/type/repository entries from the latest 100 events |

`<!-- ACTIVITY:START -->` and `<!-- ACTIVITY:END -->` delimit the activity section. `<!-- PROFILE-STATS:START -->` and `<!-- PROFILE-STATS:END -->` delimit the card markup. Do not duplicate or remove these markers. Everything outside them remains editorial and is preserved by the updater.

The Python script uses only the standard library. It validates marker pairs, filters private events and profile-repository activity, validates repository names, escapes link content, and writes atomically. The event feed is a limited recent window, not a complete contribution history. Duplicate pushes on the same UTC date to the same repository become one row; no commit totals are inferred.

## Failure behavior

API failures retain the last successful activity section. A successful empty response displays an honest empty state. Missing, malformed or recognized error SVGs do not replace existing snapshots. Generation failures appear as Actions warnings; each card can refresh independently. If all refreshes fail, the previous content remains available and the workflow retries on the next scheduled run.

Before the first successful card generation, the README uses the requested public stats endpoints. Those endpoints may be unavailable or rate-limited. Once local snapshots exist, stats no longer depend on those public image servers. The banner and skill icons still depend on their respective external services. GitHub's image cache can delay visible updates.

Only changed profile content and assets are committed. A no-change refresh makes no commit. Bot commits made with `GITHUB_TOKEN` do not recursively start another push workflow. A concurrent human push or branch protection can reject publishing; the workflow does not force-push. Rerun after resolving the branch policy or conflict.

The card actions and setup actions are pinned to immutable revisions. Review upstream security updates periodically and deliberately update those pins. The updater never logs the token. Private statistics and WakaTime are not enabled, and no extra secret is requested.

## Local checks

Run from the repository root with Python 3.12 or newer:

```sh
python -B -m unittest discover -s tests -v
python -B scripts/update_readme.py
```

The second command fetches public activity and updates the local README. `GITHUB_TOKEN` is optional locally and raises the API rate limit; configure it in the environment, never in the source. The GitHub-hosted workflow supplies its own token automatically. `--cards-dir DIRECTORY` additionally promotes validated SVGs generated by the card actions.
